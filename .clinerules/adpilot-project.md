
# AdPilot — правила работы AI-агента

## 1. О проекте

AdPilot — веб-приложение для управления рекламными кампаниями с интегрированным ИИ-ассистентом.

Цель проекта — создать полноценное работающее приложение с современным интерфейсом, серверной частью, базой данных и локальным ИИ.

Проект разрабатывается с нуля. Не предполагай, что какие-либо компоненты, зависимости, настройки или сервисы уже существуют.

## 2. Планируемые технологии

Основное направление разработки:

- Frontend: React, TypeScript, Vite.
- Backend: Node.js, Express, TypeScript.
- База данных: PostgreSQL.
- Локальный ИИ: Ollama, Qwen3:8b.

Это планируемый стек, а не перечень уже установленных технологий.

ORM, дополнительные библиотеки, инструменты и зависимости будем выбирать по мере необходимости.

Не подключай все компоненты одновременно. Разрабатывай проект последовательно.

## 3. Главные правила работы

- Перед началом работы изучай существующий проект.
- Проверяй реальные файлы, зависимости и конфигурацию.
- Не выдумывай существующие компоненты и возможности.
- Не используй библиотеки, которые ещё не установлены.
- Не создавай лишние файлы и зависимости.
- Не переписывай работающий код без необходимости.
- Не изменяй несвязанные с задачей части проекта.
- Соблюдай существующую архитектуру и единый стиль кода.
- Используй TypeScript там, где он предусмотрен проектом.
- Предпочитай понятные и поддерживаемые решения.

## 4. Работа с зависимостями

Перед использованием сторонней библиотеки:

1. Проверь, установлена ли она.
2. Изучи её назначение и необходимость для текущей задачи.
3. Объясни пользователю, зачем она нужна.
4. Предложи установку и дождись разрешения.

Не устанавливай зависимости просто на будущее.

Не обновляй Node.js, npm, Ollama и другие системные инструменты без согласования.

## 5. Порядок разработки

Разрабатывай AdPilot небольшими последовательными этапами.

Предполагаемый порядок:

1. Создание frontend и базового интерфейса.
2. Разработка backend.
3. Создание REST API.
4. Подключение PostgreSQL и выбор способа работы с базой данных.
5. Связь frontend с backend.
6. Интеграция локального ИИ через Ollama.
7. Реализация инструментов ИИ-агента.
8. Подготовка автоматизированного тестирования.

Не переходи к следующему крупному этапу, пока предыдущий не приведён в рабочее состояние.

Не создавай заранее неиспользуемые конфигурации и абстракции.

## 6. Планирование и изменения кода

Для крупных задач:

1. Изучи задачу.
2. Проанализируй связанные файлы.
3. Составь план реализации.
4. Укажи, какие файлы потребуется создать или изменить.
5. Объясни возможные риски.
6. Дождись подтверждения пользователя.
7. Реализуй задачу небольшими этапами.
8. Проверь результат.

Для небольших исправлений допускается сразу предлагать решение.

Не начинай масштабные изменения без согласования.

## 7. Качество кода

- Избегай дублирования кода.
- Разделяй интерфейс, бизнес-логику и работу с данными.
- Обрабатывай ошибки.
- Проверяй пользовательский ввод.
- Не используй фиктивные данные вместо уже работающего API.
- Не усложняй архитектуру без причины.
- Не оставляй неработающие заглушки вместо готовой функциональности.

Запускай только те проверки, инструменты для которых действительно установлены и настроены.

Не утверждай, что проверка пройдена, если она не запускалась.

## 8. Безопасность

- Не храни пароли и API-ключи в исходном коде.
- Используй переменные окружения.
- Не добавляй секретные данные в Git.
- Не предоставляй ИИ неограниченный доступ к системе или базе данных.
- Проверяй данные, поступающие от пользователей и внешних сервисов.
- Учитывай возможность Prompt Injection.
- Не выполняй опасные команды без разрешения пользователя.

## 9. Работа с локальным ИИ

Локальный ИИ должен взаимодействовать с приложением через backend.

Не подключай Ollama напрямую из frontend.

Модель должна получать доступ только к явно определённым инструментам.

Важные бизнес-операции, расчёты, цены и ограничения проверяются программным кодом, а не доверяются ответам нейросети.

Интеграцию с ИИ начинай только после подготовки необходимой серверной инфраструктуры.

## 10. Взаимодействие с пользователем

- Общайся на русском языке.
- Объясняй технические решения понятным языком.
- Учитывай, что пользователь изучает программирование.
- Не скрывай ошибки.
- Не придумывай результаты выполнения команд и тестов.
- Объясняй, что именно изменилось в коде и зачем.
- Не перегружай ответы ненужной теорией.

Пользователь должен понимать архитектуру проекта и самостоятельно разбираться в реализованном функционале.

## 11. Действия, требующие согласования

Не выполняй без разрешения:

- Удаление существующих файлов.
- Массовую перезапись кода.
- Удаление или сброс данных базы.
- Установку новых зависимостей.
- Изменение системных настроек.
- Публикацию проекта.
- Отправку данных во внешние сервисы.
- Выполнение реальных рекламных операций.

## Главное правило

Не пытайся построить весь проект за один запрос.

Сначала разбирайся с текущей задачей, затем предлагай обоснованное решение и реализуй его последовательно.

Приоритет — работающий, понятный и поддерживаемый код.
